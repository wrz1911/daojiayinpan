## 桌面端 CSP 废掉内联事件（两层根因 + rebind 方案）

- **⚠️⚠️ Tauri 的 CSP 会废掉"所有"内联 onclick(2026-09-24 定位并修复)**: 用户报"**先后天三宫标记在桌面版里怎么点都没反应, 服务器/网页版却正常**"。**先排除版本因素**: 实测内网 192.168.1.3、GitHub Pages、本地三者的 bundle 与 HTML **md5 完全相同**(`cd966363…` / `745f3d30…`), 手机已装 APK 亦**只差版本号 2 个字节**(v1.4.1 vs v1.4.2), v1.4.1→v1.4.2 的源码差异里**没有一行**碰过先后天 —— 所以是**纯运行环境差异**。根因链: ①Tauri 在**编译期**为 HTML 里的内联 `<script>`/`<style>` 计算 sha256 并注入 CSP(`tauri-codegen` 的 `CspHashes` → 运行时拼进 `script-src`, 见 `embedded_assets.rs` 的 `'sha256-{}'`); ②**按 CSP 规范, `script-src` 一旦出现 hash/nonce, 同行的 `'unsafe-inline'` 即被忽略**; ③于是**内联 `onclick` 属性全部不执行**, 而 `addEventListener` 不受影响 —— 这正解释了"长按(宫位解释)照常、短按(先后天标记)失效"; ④`jt()` 的兜底绑定写的是 `if (cur.indexOf('onGongShortPress') < 0)`, 但 `getAttribute('onclick')` **仍读得到属性字符串**, 于是误判成"已挂"而跳过 → 宫格彻底没有处理函数。**修复**: (a) 把 HTML 里两处内联脚本搬进 bundle 首位的新文件 **`qimen_app/js/qimen_boot.js`**(is-mobile 标记 + tyme4j 别名), HTML 里再无内联 `<script>` → CSP 不含 hash → `'unsafe-inline'` 恢复; (b) 兜底绑定删掉那个不可靠的 `getAttribute` 判断, 直接 `g.onclick = ...`。**⚠️ 受影响的远不止宫格**: 全项目共 **36 处内联 onclick**, 而 `jt()` 的 btns 表只兜底 10 个 —— 地八神/人八神/玄女16诀/金口诀、金口诀点选(`_jkPick`)、弹窗关闭(`this.remove()`)在桌面版里同样是废的(❌ 当时只对了一半: 走程序化兜底的恢复了, **纯内联属性的四按钮仍是废的**, 见下条 nonce 根因)。**今后别再往 HTML 里写内联 `<script>`**
- **盘面排版三处不齐的根因与修复(2026-09-28, 提交 2f10154)**: 用户报"阴干与宫内符号上下不齐"。**分析方法**: 手机离线/桌面无 JS 通道, 最终用 **WebKitGTK MiniBrowser + 本地 http 服务 + probe.js(读布局后 fetch POST 回传)** 拿到真实 DOM 坐标 —— 比像素截图反推精确百倍, 是布局类问题的首选工具(/tmp/layout_probe 相关脚本)。**三处根因**: ① buildPaipanGrid 里离9/坎1 列宽特殊化 34%(其余 33%) → 配合 .pan-cell{aspect-ratio:1/1} 使中列两宫 cell 高 ~5px → 星门行(center)低 2.4/干门行(end)低 4.8px; ② 同因导致中排宫格行矮 5px(震3/兑7 无 34% 宫); ③ 干/神 span 是 inline(高 20) 而星/门 span 因 float:right 被 block 化(高 22), 同行混排顶部错位。**修复**: #pan{table-layout:fixed}+删逐宫 width(三列 161 均分) + .panItem span:nth-of-type(1){float:left}(行首 span 同 block 化, 五类符号全 22 高)。**验证**: 八宫三行 top内 6.0/70.0/134.0 全对齐, 六盘型宫格尺寸单集合, 桌面像素 ±1px。⚠️ **MiniBrowser 有 HTTP 缓存且不带 console 输出** —— 探测时 script 引用务必加 ?v= 戳, 数据回传用 fetch POST 到本地服务(GET 长 query 会空)
- **⚠️⚠️⚠️ CSP 根因有两层: hash 只是其一, nonce 才是躲不掉的那层(2026-09-24 凌晨二次修复, rebind 方案)**: 用户报"底部地八神/人八神/玄女16诀/金口诀四按钮点击无反应"。桌面实测(main 最新构建, 03:20 二进制): 坐标(btnTable3 棕色文字带 `--wx-tu` #795548 像素定位)/点击通道(点标题栏关闭按钮有效)/盘型(时盘)逐一排除后**零响应** —— 上条"HTML 无内联 `<script>` 后内联 onclick 就能用"的结论**是错的**。铁证: 二进制 `strings` 里赫然有 **`__TAURI_SCRIPT_NONCE__`/`__TAURI_STYLE_NONCE__`** —— Tauri 2 运行时把自己的初始化脚本以 nonce 注入, 并把 `'nonce-xxx'` 追加进 CSP → 按同一规范条款 `'unsafe-inline'` 被忽略。**结论: 只要配置了 CSP, 桌面版内联 onclick/onchange/onkeydown 永远无效, 与 HTML 里有无内联 script 无关**。02fb519 当时"验证通过"是假象: 验证的先后天标记走 `g.onclick` 程序化兜底(不受 CSP 影响), 恰好掩盖了内联仍失效
  - **修复(rebind 接管, `qimen_boot.js` 末段)**: ①解析成功的内联属性 → **移除属性 + `el.onclick/onchange/onkeydown = fn` 程序化绑定** —— 属性移除后内联路径物理消失, 网页/Android/桌面三端单一路径, **无双触发**; ②解析不了的复杂语句 → 保留属性(网页/Android 仍可用)+console.warn, 要桌面支持就抽具名函数; ③**MutationObserver**(childList+subtree, 微任务去抖)收口所有 innerHTML 动态渲染(宫格/按钮/弹窗一律自动接管), 静态元素 bundle 启动时 rebind 一次; ④解析器只认 `fn()/fn(N)/fn('s')/fn(event)/window.fn()/event.stopPropagation()/event.preventDefault()/this.remove()/document.getElementById('x').remove()` 及分号组合, **不碰 eval/new Function**(CSP 无 'unsafe-eval' 会拦), 函数引用**执行时**才查 window(惰性: 静态 HTML 的 doPan 定义在 bundle 后面也没事)
  - **配套改动**: `selShanXiangDeg` 的 var/if/else 复杂内联抽成具名 `clampShanXiangDeg`/`shanXiangDegKey`(yinpan_app.js, this 语义靠接管层的 `fn.apply(host)` 保持); `build.sh` 版本戳追加 **`-g<hash>[-dirty]`** —— APP_VERSION 两次发布之间不变, 同版本内的修复部署 URL 不变 → 浏览器 30 天缓存一直命中旧文件, 表现为"修了但用户看不到"(踩过)
  - **验证**: 桌面端四按钮全响应(地八神 .on 描边 1438px / 再点取消(toggle) / 玄女16诀展开 / 金口诀面板 186024px); jsdom **21 项全过**(四按钮+静态 select 属性移除与绑定 / toggleDiBaShen 恰好 1 次 / toggle 语义 / this.remove() / stopPropagation / _jkPick(7) 参数 / window.fn() 前缀 / 宫格短按 toggle 闭环)
  - **教训**: ①**"先探测内联是否有效、再决定挂不挂"必翻车**(575ac9b: WebKitGTK 的 `probe.click()` 不触发属性 handler → 内联有效也误判失效 → 委托与内联同时执行 → toggle 双触发) —— 要么纯内联要么纯程序化, 别两头下注; ②验证 CSP 修复时**必须验证"只有内联属性、没有程序化兜底"的元素**(四按钮正是), 走了兜底的元素会给出假阳性; ③Tauri 的 CSP 行为要用 `strings` 二进制/运行时实际 CSP 求证, 别拿"配置文件里写了 unsafe-inline"当生效依据; ④jsdom 验证"恰好一次"时, spy 挂 window 导出会漏 —— `_bindActionButtons` 闭包捕获的是 IIFE 内部引用, 拦不到, 用**功能结果**(xhBar 出现/消失)反推触发次数更可靠
- **桌面版 UI 的自动化验证手法(2026-09-24, 本次定位就靠它)**: WSLg 可用(`DISPLAY=:0`), 于是 Tauri 界面可以完全脚本化验证 —— ①`setsid nohup ./src-tauri/target/release/app &` 启动; ②`WID=$(xdotool search --name '阴盘' | head -1)` 取窗口; ③`eval "$(xdotool getwindowgeometry --shell $WID)"` 拿到窗口左上角 **X/Y** —— **窗口内坐标必须加上它才是屏幕坐标**; ④`xdotool mousemove $((X+..)) $((Y+..)) click 1` 点击; ⑤`magick import -window $WID out.png` 截图, `magick compare -metric AE a.png b.png null:` 数差异像素(AE 输出的是差异像素个数, 0 = 完全没响应)。⚠️ **三个坑**: a) **`import -window root` 在 ImageMagick 7 下报 "missing an image filename"**, 必须用 `-window <窗口ID>`; b) **`pkill -f 'target/release/app'` 会匹配到自己这条命令行、把自己杀掉**(与 `pkill -f adb` 同一个坑), 要用 `pkill -x app`; c) 窗口内容**会滚动**, 按钮区常在首屏之外, 点之前先 `xdotool click 5` 滚下去并截图确认坐标。**判读结果时别只看"有没有变化"**: 先后天标记的效果是"三宫同时变色+角标", 用 `XIANTIAN_GONG`/`HOUTIAN_GONG` 的映射反查才能确认点中的是哪一宫(本次点击的宫位与预期差一格, 但映射精确吻合, 反而更可信)

- **宫位长按(2026-09-22 用户要求, 同日修订)**: **时盘(1)/刻盘(2)/山向(4)/命理(6)** 四种盘型的宫位改为**长按 550ms 弹出宫位解释**, 四者**共用同一套逻辑**(`_bindGridLongPress` 事件委托 + `showPalace` 同一个解释渲染), 不各写一份 —— 区分盘型只靠一个数组常量。**心盘(3) 不在其列**: 宫位点击仍是打开宫位编辑器(`showXinpanEditor`); 穿壬(5) 无宫位解释。目的: 移动端防误触。实现三处: ①`LONG_PRESS_PAN_TYPES=[2,3,4,6]` 常量(yinpan_app.js:13622); ②`buildPaipanGrid` 对这四型**生成时就不挂内联 onclick**(`noInlineClick`, 与既有的 noClick 同思路 —— 靠渲染后清理容易漏); ③`_bindActionButtons` 改用 `_bindLongPress` 绑定。**同时静默启用了山向/命理的宫位解释**(原先 `showPalace` 开头 `panType===4||5||6` 直接 return) —— 数据本就齐备: 引擎 `pals[g]` 直接带 `shen/tian/di/xing/men/anGan`, 山向的 `_palaces` 是规范格式, 命理的 `_palaces` 引用 `qr.pals[g]`, 故**未改 qimen_mingli.js**。⚠️ **踩坑(已修): 山向/命理的符号是"简称", 与主盘格式不一致** —— 山向/命理的 `window._palaces` **直接引用引擎数据**, `shen/xing/men` 存的是**简称**('天'/'柱'/'生'); 而时盘/刻盘的来自 `renderPan` 解析, 存的是**全名**('九天'/'天柱'/'生门')。解释表(`SHEN_INFO`/`XING_INFO`/`MEN_INFO` 及 `*_FULL`/`WUCHENG_*`)的键全是全名 → 简称一路落空, 山向/命理弹窗里**满屏 undefined**。修法: `showPalace` 开头加 `_toFull(val, ABBR)`(简称经 ABBR 反查全名)归一化, 之后全程用 `pShen/pXing/pMen`, 四个模式这才真正共用同一套解释数据。**同时修掉一个运算符优先级 bug**: `'八神·'+(SHEN_ABBR||{})[x]||x` 因 `+` 优先于 `||`, 等价于 `('八神·'+…)||x` —— 查不到时得到的是**非空字符串 `'八神·undefined'`**, 兜底永不生效, 必须写 `'八神·'+((…)[x]||x)`
- **心盘长按"留白"与触屏合成鼠标事件(2026-09-22)**: 用户要求 **心盘短按=宫位编辑器, 长按暂不定义(预留后续功能)**。仅把心盘排除出 `LONG_PRESS_PAN_TYPES` **不够** —— Android WebView 在 `touchend` 后还会**补发一套合成的 `mousedown`/`mouseup`/`click`**, 于是"长按"松手时那次 click 照样走了短按的 onclick, 把编辑器打开了。三个要点: ①`begin` 里**绝不能重置**"抑制标志"(合成 mousedown 也会进 begin, 一重置就把标志清掉, 实测正是这里失效); ②长按成立时置位, 并在 document 的 **capture 阶段**用 `stopPropagation()+preventDefault()` 拦掉紧随的 click; ③加 **1.5 秒兜底超时**, 万一 click 没派发(被系统手势吃掉)标志不会残留、误拦下一次真短按。心盘长按的后续功能直接加在 `_bindGridLongPress` 里 `if (isExplain)` 的 else 支即可
